Drop the branded-key helpers in favour of i18next's native TypeScript support, porting
[wolfstar-project/stars-components#30](https://github.com/wolfstar-project/stars-components/pull/30).

**Breaking:** `T`, `FT`, `resolveKey`, `resolveUserKey`, `TypedT`, `TypedFT`, `Value`, `Values` and
`Difference` were removed. Keys are now plain strings typed through the `CustomTypeOptions`
augmentation generated by
[`@wolfstar/i18next-type-generator`](https://www.npmjs.com/package/@wolfstar/i18next-type-generator),
and `resolveKey(target, key, options)` becomes `getSupportedLanguageT(target, key, options)` (and
`resolveUserKey` its `getSupportedUserLanguageT` counterpart), keeping the call shape those helpers
had.

`LocalePrefixKey` is no longer hardcoded to `commands/<file>:<key>`; it is now
`` `${string}${LocaleSeparator}${string}` ``, with the new `LocaleSeparator` type read from
i18next's `TypeOptions["nsSeparator"]`.

`getSupportedLanguageT` and `getSupportedUserLanguageT` resolve the key when one is passed, and
still return the bound `TFunction` when it is not.

`InternationalizationHandler#getT` takes an optional namespace and returns a `TFunction<Ns>` bound
to it, so its keys can be written without the `<namespace>:` prefix.
